# BitMVP —— 产品化架构设计（bitmvp.com）

> 目标：把 4 个散装 demo 整合成**一个看起来像完整公司产品线的产品闭环**，作为拿下 Bitget offer 的敲门砖
> 日期：2026-09-04

---

## 一、核心思路：从「作品集」到「产品套件」

### 三种境界的差距

| 层次 | 面试官看到 | 评价 |
|---|---|---|
| ❌ 散装 demo | 「4 个独立的练习项目」 | 「做过一些 Web3 练习」 |
| ⚠️ 简单整合 | 「一个作品集站点，有几个 demo」 | 「作品集做得不错」 |
| ✅ **产品化闭环** | 「一套有产品思维的完整解决方案」 | **「这人懂产品，能独立负责一块业务」** |

### 关键转变

> 不是「我做了 4 个 demo」，而是「我做了一个叫 **BitMVP** 的链上资产工作台，它有 4 个模块」。

**判断标准**：删掉任何一个模块，产品就不完整 —— 这才是闭环，不是拼盘。

## 二、品牌与定位

### 域名即品牌

`bitmvp.com` 这个名字本身是资产，要把它用足：

| 拆解 | 含义 | 传递的信号 |
|---|---|---|
| **Bit** | 比特 / 区块链 | Web3 属性 |
| **MVP** | Minimum Viable Product | 精益产品思维、快速验证能力 |

→ **品牌名：BitMVP**
→ **Slogan：One Account, Full Onchain Control**（一个账户，全链路掌控）
→ **中文：链上资产智能工作台**

> 💡 这个名字的妙处：它同时暗示了「你懂 Web3」和「你有产品方法论」。MVP 这个词对产品经理岗位尤其加分。

### 产品定位一句话

> **BitMVP 是一个链上资产智能工作台 —— 让你看清资产、执行交易、洞察链上动向，并用自然语言完成这一切。**

## 三、产品矩阵（四大模块）

统一命名为 `BitMVP + 模块名`，这是真实公司产品线的命名方式（对标 Notion AI、Figma Dev Mode 的命名逻辑）：

| 模块 | 名称 | 一句话 | 对标 Bitget | 技术核心 |
|---|---|---|---|---|
| ① | **BitMVP Portfolio** | 多链资产全景看板 | Bitget Wallet 资产页 | wagmi + viem 多链读取 |
| ② | **BitMVP Swap** | DEX 聚合交易台 | Super DEX | 合约交互、授权、交易状态机 |
| ③ | **BitMVP Radar** | 链上资金雷达 | Wallet Alpha（聪明钱） | Event Log 解析、数据聚合 |
| ④ | **BitMVP Copilot** | AI 链上助手 | GetAgent / Agent Hub | Function Calling、MCP |

## 四、闭环设计 ⭐ 这是整个方案的灵魂

闭环要成立，必须同时做到**用户流闭环**和**数据流闭环**。只有前者是 PPT，两个都有才是真产品。

### 4.1 用户流闭环：查看 → 决策 → 执行 → 智能辅助

```
        ┌─────────────────────────────────────────┐
        │                                         │
        ▼                                         │
   ① Portfolio                              ④ Copilot
   「我有什么？」                           「帮我搞定」
   看清多链资产                            自然语言下达指令
        │                                         ▲
        │ 发现：Base 上 ETH 占比过高               │
        ▼                                         │
   ② Swap                                  ③ Radar
   「我要调仓」                            「别人在买什么」
   执行交易、追踪状态                      链上资金流、聪明钱
        │                                         ▲
        │ 交易后：这个币值得拿吗？                 │
        └─────────────────────────────────────────┘
```

**讲给用户听的故事**：
> 你在 Portfolio 发现自己 Base 链的 ETH 占比太高 → 去 Swap 换成 USDC → 换完想知道「聪明钱最近在买什么」→ 打开 Radar 看资金流向 → 数据太多懒得分析 → 直接问 Copilot：「帮我看看这个地址最近在买什么，值不值得跟」→ Copilot 调用 Radar 和 Portfolio 的数据给出回答 → 你据此再回到 Portfolio 调整 → **闭环完成**。

### 4.2 数据流闭环：Copilot 是「统一入口」，其余三模块是「能力底座」

这是让架构自洽的关键 —— **不是硬凑，而是真实的技术依赖**：

```
                    ┌──────────────────────┐
                    │   BitMVP Copilot     │  ← 统一入口（AI 层）
                    │  (Function Calling)  │
                    └──────────┬───────────┘
                               │ 调用工具
         ┌─────────────────────┼─────────────────────┐
         ▼                     ▼                     ▼
  ┌─────────────┐      ┌─────────────┐      ┌─────────────┐
  │ getBalance  │      │  getQuote   │      │ getSmartMoney│
  │ (Portfolio) │      │   (Swap)    │      │   (Radar)    │
  └──────┬──────┘      └──────┬──────┘      └──────┬───────┘
         │                    │                    │
         └────────────────────┼────────────────────┘
                              ▼
                  ┌───────────────────────┐
                  │   统一链上数据服务层    │  ← Node.js + Supabase
                  │  (RPC / 索引 / 缓存)   │     复用你的后端优势
                  └───────────┬───────────┘
                              ▼
                     Alchemy / QuickNode / CoinGecko
```

**为什么这个闭环是真的**：
- Copilot 不是「另一个独立 demo」，它**真的调用**前三个模块封装好的数据能力
- 四个模块共享**同一套数据服务层**（不是各调各的 API）
- 技术上按 **MCP（Model Context Protocol）** 规范暴露工具 → 正好呼应 Bitget Agent Hub

> ⚠️ **这点极其重要**：如果你的 4 个模块各自独立调 API、Copilot 也只是个聊天框，那面试官一眼就看出是拼盘。共享数据层 + 工具调用，才是真闭环。

## 五、网站结构（bitmvp.com 站点地图）

按真实产品公司官网来组织：

```
bitmvp.com
├── /              首页（产品官网风格）
│   ├── Hero：产品定位 + 一句话价值
│   ├── 产品矩阵：4 个模块卡片（点击进入）
│   ├── 闭环流程图：可视化展示产品逻辑
│   ├── 技术架构：数据层 + AI 层说明
│   └── CTA：立即体验 / 查看文档
│
├── /portfolio     BitMVP Portfolio（可交互 Demo 1）
├── /swap          BitMVP Swap（可交互 Demo 2）
├── /radar         BitMVP Radar（可交互 Demo 3）
├── /copilot       BitMVP Copilot（可交互 Demo 4）
│
├── /docs          产品文档（API、架构说明、快速开始）
├── /changelog     更新日志（体现持续迭代能力）
└── /about         关于（产品设计理念 + 作者背景）
```

### 首页为什么关键

面试官 80% 的时间在首页。**首页必须在 15 秒内传达**：
1. 这是一个**产品**，不是作品集（用产品官网语言，不用「我的作品」这类措辞）
2. 它有**清晰的闭环逻辑**（放一张流程图，胜过千言万语）
3. 它**真能用**（每个模块有明确入口，且真的能跑）

## 六、让它看起来像「真公司产品」的 7 个细节

这些细节决定「像不像」，成本不高但效果显著：

| # | 细节 | 具体做法 |
|---|---|---|
| 1 | **统一品牌视觉** | Logo、配色、字体全局统一；建议深色科技感或 Bitget 风格的青绿主色 |
| 2 | **统一设计系统** | 一套组件库（按钮/卡片/表格/Toast）复用，4 个模块视觉完全一致 |
| 3 | **产品页 + 应用双层** | 每个模块先有「产品介绍页」（价值说明），再进「实际可用应用」 |
| 4 | **真实的更新日志** | `/changelog` 记录每次迭代，体现持续交付能力 |
| 5 | **产品文档** | `/docs` 写清架构、API、快速开始 —— 工程素养的直接体现 |
| 6 | **统一的 Footer** | 公司信息、产品链接、文档、联系方式，像真实产品 |
| 7 | **讲一个「为什么」** | 首页讲述产品要解决什么问题、为谁解决 —— 产品思维的证明 |

### 措辞上的关键转变

| ❌ 不要这样写 | ✅ 要这样写 |
|---|---|
| 「我的毕业设计 / 练习项目」 | 「BitMVP 是一个…的产品」 |
| 「Demo 1：钱包连接」 | 「Portfolio：多链资产全景看板」 |
| 「使用说明」 | 「快速开始 / Quick Start」 |
| 「项目展示」 | 「产品矩阵 / Products」 |

## 七、战略价值：与 Bitget 的精准呼应

这是这套设计的隐藏杀招 —— **BitMVP 的产品结构几乎就是 Bitget Wallet 的产品结构**：

| BitMVP 模块 | ≈ Bitget 对应产品 |
|---|---|
| Portfolio | Bitget Wallet 资产页 |
| Swap | Bitget Wallet Swap / Super DEX |
| Radar | Bitget Wallet Alpha（聪明钱追踪） |
| Copilot | GetAgent / Agent Hub |

**这意味着**：面试官打开 bitmvp.com，看到的是一个**已经理解并复刻了他们产品逻辑**的人。这比任何自我介绍都有说服力。

> ⚠️ **表达策略**：网站上**不要明说**「这是对标 Bitget 做的」（显得刻意）。让产品自己说话。**在面试时口头点出**：「我做 BitMVP 时研究了主流钱包的产品结构，发现资产—交易—洞察—AI 是一个完整闭环…」—— 这时面试官自己会对上号。

## 九、风险与注意

| 风险 | 后果 | 规避 |
|---|---|---|
| **空壳化** | 只有漂亮介绍页，点进去不能用 | 每个模块必须真能跑；宁可少一个模块，不要假模块 |
| **数据是 mock** | 面试官一试就穿帮 | 链上数据必须真实（测试网/主网只读均可） |
| **AI 是假对话** | Copilot 只是预设回复 | 必须真调用工具、真查数据，回答要能溯源 |
| **过度包装** | 简历写得太满，面试兜不住 | 每个功能都要能讲清实现细节与权衡 |
| **闭环是画的** | 流程图好看，模块间无实际依赖 | 务必共享数据层 + Copilot 真调用工具 |

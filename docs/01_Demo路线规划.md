### Demo 1：多链资产看板（Multi-Chain Portfolio）

**一句话**：连接钱包，一个页面看清你在多条链上的全部资产。

**核心功能**
- 钱包连接（MetaMask / WalletConnect）+ 断开 + 切换账户
- 多链切换与聚合：Ethereum、Base、Arbitrum、Polygon、BSC（至少 3 条）
- 显示：原生币余额、ERC-20 代币列表（图标 + 余额 + 美元估值）
- 总资产 USD 汇总、24h 涨跌
- 加载 / 错误 / 未连接 三态处理（Web3 应用的必备素养）

**技术栈**
```
Next.js (App Router) + TypeScript
wagmi v2 + viem        # 链上读写核心
RainbowKit             # 钱包连接 UI（基于 wagmi）
TanStack Query         # 请求缓存（wagmi 内置依赖）
Tailwind CSS + shadcn/ui
Alchemy / QuickNode    # 多链 RPC（免费额度够用）
CoinGecko API          # 代币价格
```

**要补的知识**（做之前先学）
| 知识 | 学到什么程度 | 为什么必须 |
|---|---|---|
| 账户 / 地址 / 公钥私钥 | 理解即可 | 前端不碰私钥，但要懂地址从哪来 |
| 助记词 & HD 钱包（BIP39/32/44） | 理解原理 | 面试必问「钱包怎么派生多链地址」 |
| EVM 与 Chain ID | 记住常用链 ID | 多链切换的基础 |
| JSON-RPC 与 Provider | 会用 | 所有链上读取都走它 |
| ERC-20 标准（balanceOf / decimals / symbol） | 熟练 | 读代币余额的 100% 考点 |
| BigInt 与精度处理 | ⚠️ 必须熟练 | 新手最常踩的坑：`1e18` 转换 |
| Gas 基础概念 | 了解 | 后面 Demo 2 要用 |

**验收标准（DoD）**
- [ ] 能在测试网 + 主网（只读）都跑通
- [ ] 切链后资产正确刷新，无缓存串味
- [ ] 未连接 / 加载中 / RPC 失败 三态 UI 完整
- [ ] 余额精度正确（不会出现 `0.000000000000000001`）
- [ ] 部署上线，手机浏览器可访问

### Demo 2：Swap 交易台 ⭐ 最重要

**一句话**：对标 Bitget Wallet 的 Swap，完整跑通「报价 → 授权 → 下单 → 追踪」全流程。

**这是整个作品集的核心**。面试官判断你「能不能做钱包」，80% 看这个。

**核心功能**
- 代币选择（From / To）+ 金额输入 + 实时报价
- 价格影响 / 滑点设置 / 最低接收数量（minReceived）
- Gas 估算 + 三档速度（慢 / 普通 / 快）
- **授权流程**：检测 allowance → approve → swap（两笔交易的正确编排）
- 交易状态机：签名中 → pending → 成功/失败，含区块浏览器链接
- 失败原因解析与友好提示（滑点不足 / Gas 不足 / 用户拒绝）

**技术栈**（Demo 1 基础上增加）
```
Uniswap V2/V3 Router 合约         # 或 0x / 1inch 聚合 API
viem 的 readContract / writeContract / waitForTransactionReceipt
Tenderly 或 Alchemy 交易模拟       # 加分：下单前模拟
```

**要补的知识**
| 知识 | 程度 | 为什么是考点 |
|---|---|---|
| AMM 自动做市（恒定乘积 x·y=k） | ⚠️ 必须理解 | 面试几乎必问「Swap 价格怎么算出来的」 |
| 流动性池 / LP / 手续费 | 理解 | 理解价格影响的来源 |
| 滑点、价格影响、MEV 三明治攻击 | 理解 + 能讲 | 钱包产品的核心风控点 |
| ERC-20 approve / allowance 机制 | ⚠️ 熟练 | 「为什么要先授权」是经典题 |
| 交易生命周期（nonce → 签名 → 广播 → 打包 → 确认） | ⚠️ 熟练 | 前端状态机设计依据 |
| 合约 ABI 与读写分离 | 会用 | readContract vs writeContract |
| ⚠️ 无限授权的安全风险 | 了解 | Bitget Wallet 有「授权管理」功能 |

**验收标准**
- [ ] 在测试网（Base Sepolia / Sepolia）真实完成过一笔 Swap
- [ ] 授权状态正确判断（已授权足量则跳过 approve）
- [ ] 交易 pending 期间 UI 不卡死、可查进度
- [ ] 失败场景有明确提示（至少覆盖 3 种失败）
- [ ] 能讲清楚「为什么滑点设太低会失败」

### Demo 3：链上追踪看板（聪明钱 / 资金流）

**一句话**：可视化监控指定地址或代币的链上活动，对标 Wallet Alpha 的「聪明钱追踪」。

**这个 demo 体现产品 sense 与数据处理能力**，是拉开与普通前端差距的地方。

**核心功能**
- 输入地址 → 展示其资产分布、近期交易流水
- 大额转账监控（筛选 + 时间线）
- 代币维度：持有人分布、近期大额买卖
- 可视化：资金流向图 / 交易热力图 / 涨跌曲线
- 可选：Top 地址排行榜（用公开数据构造「聪明钱」指标）

**技术栈**（新增）
```
Alchemy / Covalent / Etherscan API   # 交易历史（自己扫区块太慢）
eth_getLogs 解析 Event Log           # 理解原理必做一次
Recharts 或 visx                     # 图表
Node.js + Supabase                   # ⭐ 复用你的后端能力：抓取 → 存储 → 聚合
```

> 💡 **你的优势**：这是把 Node.js + Supabase 经验变现的地方——自己写一个链上数据索引服务，比纯前端调 API 有说服力得多。

**要补的知识**
| 知识 | 程度 |
|---|---|
| 区块结构与交易回执 | 理解 |
| Event / Log 机制（topics、data 解码） | ⚠️ 至少手动解析一次 Transfer 事件 |
| 索引器概念（The Graph 是什么、为什么需要） | 了解 |
| 数据聚合与缓存策略 | 熟练 |

**验收标准**
- [ ] 至少手动用 `eth_getLogs` 解析过一次 ERC-20 Transfer 事件（不只用 API）
- [ ] 图表可交互、移动端可读
- [ ] 有明确的「洞察」输出（不只是数据罗列）
- [ ] 数据量上去后不卡（有分页/虚拟滚动/缓存）

### Demo 4：AI 链上助手（加分项，但强烈建议做）

**一句话**：用自然语言问链上问题，AI 调用工具查询并回答——对标 **GetAgent + Agent Hub（MCP）**。

> ⚠️ **战略意义**：Bitget 2026 最激进的方向就是 AI Agent（GetAgent 已超 100 万用户，Agent Hub 是唯一同时支持 MCP / Skills / REST / WebSocket 的交易所）。
> 你本来就在深研 AI Coding / Skills / MCP 体系——**这是你相对其他候选人最大的护城河**。

**核心功能**
- 对话界面：中文自然语言提问（如「这个地址最近在买什么？」）
- LLM Function Calling → 调用你封装的链上工具（查余额、查交易、查代币信息）
- 工具编排：支持多步调用（先查地址 → 再查代币 → 汇总）
- 可选进阶：按 **MCP 协议**暴露工具，呼应 Bitget Agent Hub

**技术栈**
```
LLM API（Function Calling / Tool Use）
自定义工具层（封装 Demo 1–3 的查询能力）
可选：MCP Server 实现
```

**验收标准**
- [ ] 至少 3 个可用工具，能稳定多步调用
- [ ] 回答结果可溯源（附区块浏览器链接，防幻觉）
- [ ] 有清晰的「能力边界」提示（不编造数据）
- [ ] 能讲清楚与 Bitget GetAgent 的异同与改进点

## 三、基础知识地图（按优先级分层）

你说「基础不太行」——**不用系统啃完再动手**，而是「做 demo 时缺什么补什么」。但下面这张图让你心里有数：

### 🔴 P0 必须掌握（不懂就写不动）
1. 账户体系：私钥 → 公钥 → 地址的推导关系
2. 助记词与 HD 钱包：BIP39 / BIP32 / BIP44 派生路径（`m/44'/60'/0'/0/0`）
3. EVM 基础：账户模型、Gas、Nonce、交易结构
4. ERC-20：`balanceOf` / `transfer` / `approve` / `allowance` / `decimals`
5. JSON-RPC 与 Provider / Signer 的区别
6. **BigInt 精度处理**（wei / gwei / ether 换算）
7. viem + wagmi 的核心 Hook 用法

### 🟡 P1 应该理解（面试会问）
8. AMM 恒定乘积与滑点 / 价格影响
9. 交易完整生命周期与状态机
10. MEV / 三明治攻击与钱包的防护手段
11. 多链差异（L2 的 Gas、确认速度、RPC 行为不同）
12. 常见代币标准：ERC-721 / ERC-1155
13. 钱包安全：钓鱼、签名风险（permit / 盲签）、授权管理

### 🟢 P2 了解即可（加分、拓宽视野）
14. 钱包连接协议：WalletConnect v2、EIP-6963
15. 账户抽象 ERC-4337、Gas 代付、MPC 钱包
16. 索引器 The Graph 的工作原理
17. PayFi / RWA / 稳定币结算（Bitget 的战略方向）
18. Solana 等非 EVM 链的地址与交易模型差异

## 六、简历与面试话术预埋

作品做完后，每一段经历要能这样讲（STAR 结构）：

**Demo 2 示例话术**
> 「我做了一个对标 Bitget Wallet Swap 的交易台。难点在两点：一是**授权与下单的两笔交易编排**——我先判断 allowance 是否足量，足量则跳过 approve 减少一次用户签名；二是**交易状态机**，把签名中/pending/成功/失败拆成明确状态并分别处理，失败时解析 revert reason 给出可读提示。我还做了滑点与价格影响的前端预校验，避免用户白付 Gas。」

**面试官可能追问 & 你要能答**
- 为什么 Swap 要先授权？（ERC-20 安全模型）
- 滑点设太低为什么会失败？（价格影响 vs 滑点容忍度）
- 多链下 RPC 行为有什么不同？（L2 确认速度、Gas 估算差异）
- 怎么防止用户在你的前端签下恶意交易？（交易模拟、合约校验、来源白名单）

## 七、风险与坑（提前避让）

| 坑 | 表现 | 规避 |
|---|---|---|
| 陷入「先学完再动手」 | 学两个月还没写一行代码 | 严格按 S0→S5 阶段走，每阶段必出产出 |
| 精度错误 | 余额显示 `0.000000000000000001` | 早期就把 BigInt / decimals 处理写成工具函数 |
| 用公共 RPC | 限流、超时、数据不准 | 一开始就申请 Alchemy/QuickNode |
| 忽视移动端 | 作品在手机上一团糟 | Bitget Wallet 是移动优先产品，作品必须手机可读 |
| 主网测交易 | 花真钱 | 一律测试网 / Anvil 本地分叉 |
| 只堆功能不讲故事 | 面试官看不懂价值 | 每个 demo 配一段「它证明了什么」 |

## T1 · 我卡在哪（0:00–0:40）

〔屏幕：Etherscan 上打开 vitalik 的地址页，各种数字〕

> 说下我为什么要做这件事。
>
> 前几天我从交易所提币到自己的钱包，转完心里一直没底：到底到没到？我想自己确认，不经过任何人。结果打开 Etherscan，一堆数字看得我发懵——地址、余额、这些数到底存在哪，我一条都答不上来。
>
> 所以我决定从最笨的地方开始：不借助任何现成产品，自己在终端里把「一个地址有多少 ETH」查出来。查的过程，就是我今天要搞懂的过程。

## T2 · 以太坊到底是什么（0:40–1:50）

〔屏幕：笔记卡「以太坊 ≈ 一本人人持有的账本」〕

> 动手之前我得先补课，不然连问什么都问不出来。第一个问题：以太坊到底是什么？
>
> 我以前的理解是「类似支付宝的东西」。查了资料发现完全不是——支付宝是银行帮你记账，它说了算；以太坊是**一本全世界共用的账本**，每个人手里都有完整的一份副本，一笔账要被网络里大多数人认可才算数。没有任何一家公司能偷偷改它——就算改了，跟其他人的副本对不上，也不会被认可。
>
> 我一下子明白 Etherscan 为什么能查了：它不是官方，它只是也在读这本公开的账。那我理论上自己也能读。
>
> ETH 就是记在这本账上的钱。（停顿）我的目标其实特别朴素：翻到账本里我这个地址那一行，看一眼。

## T3 · 地址又是什么（1:50–2:50）

〔屏幕：笔记卡「地址 = 账号，可以公开」〕

> 第二个我答不上来的词：地址。`0xd8dA6BF…` 这串 42 位的字符到底是什么？
>
> 查了：它是**账号**。别人给你转钱，转到这个号上。有两个我以前一直没敢确定的点，这次一并确认了：
> 1. 地址是公开的，随便发给别人都没事——它是银行卡号，不是密码。而且整个账本上每个地址的余额本来就公开可查，这是我能查到别人余额的原因；
> 2. 链上除了这种「人的地址」，还有另一种地址里面住着程序，叫合约。（停顿）我先把这个记在笔记里，预感以后会撞上。

## T4 · 钱包里没有钱？（2:50–3:30）

〔屏幕：笔记卡「钱包 = 钥匙串，钱一直在链上」〕

> 接着我被一个想当然的认知绊了一下：我一直以为钱是存在 MetaMask 里的。
>
> 查了才知道，**钱包里根本没有钱，钱一直在链上**——记在账本我地址名下的那一行。钱包里真正存的东西叫私钥：地址由私钥推导出来，谁拿着私钥，谁能动这笔钱。
>
> 所以钱包其实是个钥匙串：手机丢了无所谓，钱在链上；私钥丢了，钱还在链上，但我永远动不了它了。「不是你的私钥，就不是你的币」——我现在能理解这句话为什么是头号警告了。
>
> 好，概念这关过了。现在我真正的问题来了：账本到底在哪，我怎么翻它？

## T5 · 那数据到底在哪——节点（3:30–4:20）

〔屏幕：切到 VSCode 空目录〕

> 我的第一反应：调个接口呗。（停顿）但调谁的接口？以太坊不是一家公司、没有一个官网挂个「查余额 API」。
>
> 刚才说了，账本的副本在一种叫**节点**的机器上，每台都存着完整状态。那我自己跑一台行不行？我去查了下：全量节点要同步 TB 级数据，我的机器和耐心同时劝退。

## T6 · 借别人的节点问——RPC（4:20–5:00）

> 自己的不行，那就借别人的。网上有公开的节点入口，免费对任何人开放，这类入口叫 **RPC**。
>
> 我对 RPC 的理解暂时只敢到这一步：**一个 HTTP 地址，我发请求，它把账本状态答给我**。再深的我不装懂，够用就行。
>
> 用的就是这个公共 RPC：`https://ethereum-rpc.publicnode.com`。免费肯定有代价——我猜是限流，到时候撞上再说。
>
> 〔可选镜头 · 推荐：在用库之前，先用 curl 看看 RPC 长什么样〕
>
> 〔终端：`curl -X POST <rpc-url> -d '{"jsonrpc":"2.0","method":"eth_getBalance","params":["0xd8dA…","latest"],"id":1}'`〕
>
> 我先裸着试了一次：它回了一串 `0x59…` 十六进制。原来最原始的读链是这样——能跑，但参数要手工拼、结果要自己解码，脏活不少。我决定找个库把这些包掉。

## T7 · 找个库（5:00–5:20）

> JS 生态里主要有 ethers 和 viem 两个选择。我挑了 viem——理由就一条：TypeScript 类型做得好，写起来舒服。我没做深入对比，跑通再说，选错了以后再换。
>
> 〔屏幕：`npm init -y && npm i viem && npm i -D tsx`〕
>
> 项目里已经装好了，clone 仓库的话可以跳过。

## T8 · 建立连接：client（5:20–6:00）

〔屏幕：新建 `lab/labs/01-balance.ts`，边写边讲〕

```ts
import { createPublicClient, http } from "viem";
import { mainnet } from "viem/chains";

const client = createPublicClient({
  chain: mainnet,
  transport: http("https://ethereum-rpc.publicnode.com"),
});
```

> 写出来就两行，其实把我前面查明白的事翻译了一遍：`chain` 是「我问以太坊主网」，`transport` 是「我去问这个节点」。
>
> 我隐隐觉得这个 `client` 会跟我很久——以后读代币、查报价，估计都在它身上加方法。先立此存照，后面几集验证。

## T9 · 第一问（6:00–6:50）

```ts

const balance = await client.getBalance({ address });

console.log(address);
console.log(balance);
```

> `getBalance`，名字看起来就很直白。我这次**故意**不做任何格式化——我想知道原始答案长什么样。
>
> 〔终端：`npx tsx lab/labs/01-balance.ts`〕
>
> 出来了：`5773499921329373953`。（停顿）……这是个什么数？五千多万万亿？vitalik 再富也没这么离谱。账本给我的就是这串原始数字——它没打算让我直接看懂。行，我自己来解。

## T10 · 这数怎么这么大——单位（6:50–7:30）

> 我去查了这串数的含义：链上所有金额都是**整数**，记的是最小单位。以太坊的最小单位叫 wei，1 ETH = 10^18 wei。
>
> 为什么这么极端？我一开始以为是技术炫技，后来想明白了：账本上不能有浮点数——整数除法最多丢余数，浮点运算是真的会丢钱。这个猜想我先记着，第三集专门去验证。
>
> 所以现在我只需要除以 10^18。查了下 viem 自带现成的：

>
> `formatEther` 就是替我做了这一下除法。再跑。

## T11 · 三个实验（7:30–8:10）

〔终端：连续三次实测〕

> 数字能看了，我多玩两下，看看有没有意外：
>
> 第一跑，vitalik 的地址——5.77 ETH，跟 Etherscan 上对得上，成了。
>
> 第二个实验，换一个空地址——输出 0。我第一反应是「这地址不存在？」查了下发现不是：链上任何合法地址都存在，只是账本上没记它的钱。又一个想当然被修正。
>
> 第三个实验，我故意把 RPC 换成一个坏的——（停顿）报错了。意料之中，公共的免费服务就是会抽风。今天只诊断不治疗，这个坑什么时候真正咬到我，什么时候治（第五、六集）。

## T12 · 我带走的 + 新问题（8:10–8:40）

> 这集跑下来，我自己带走的认知有四条：
> 1. 以太坊是改不动的公共账本，ETH 是账上的钱，地址是账号，钱包只是钥匙——四个词终于不再是黑话；
> 2. 读链 = 向 RPC 节点发只读请求，不需要钱包、不需要私钥、不花一分钱；
> 3. 账本上的余额是最小单位的整数，展示前要自己换算；
> 4. `client` 建一次，我赌它后面一直用得上。
>
> 但是。（停顿）我马上又撞上了一个新问题：真实钱包里的大头根本不是 ETH，是 USDT、USDC 这些 ERC-20 代币——还记得 T3 我记的那条笔记吗，「有另一种地址里面住着程序」。这些代币本身就是一份份合约，`getBalance` 根本管不到。难道一个代币发一次请求？我数了数这个地址有 30 个代币……
>
> 下一集，我去试试怎么把 30 次请求打进 1 次。

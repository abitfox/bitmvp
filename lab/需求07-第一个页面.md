# 需求 07《每次跑脚本太麻烦：第一个页面》策划案 · 思考流口播版

目标时长 7.5 分钟。视角铁律见 `lab/00-内容标准.md`。上集钩子：数据能力成型，凭什么不能随时打开浏览器看。本集是第一轮 UI 整合：只做展示，不做样式和交互。

## 思考主线（先看骨架）

```
T1 终端的局限 → T2 浏览器直接打节点行不行 → T3 拆解：三层结构
→ T4 API route 包数据函数 → T5 页面 + react-query → T6 实测 → T7 收束
```

## T1 · 终端的局限（0:00–0:40）

〔屏幕：终端里敲命令跑估值表的回放〕

> 每次看资产都要：开终端、想命令、敲、等。数据能力全齐了，体验还停在原始社会。我要的是一个「打开就能看」的东西。
>
> 顺手明确了边界：这一集只做**展示**——把终端那张表搬上网页。交互、样式、连接钱包，全部不做，每样都是后面有需求了再说。

## T2 · 浏览器直接打节点行不行（0:40–1:40）

> 第一个问题就把我问住了：页面里能不能直接调 viem 打节点，跳过后端？
>
> 我去查了：技术上可以，但有两个坑等我——浏览器的跨域限制（CORS）不是每个节点都配合；而且今天全是公开数据无所谓，以后一旦有需要密钥的调用（比如 AI），密钥放前端等于裸奔。
>
> 所以折中方案：浏览器只跟我自己的一个「中间层」说话，中间层去干读链的活。这就是为什么 Next.js 的 API route 值得存在。

## T3 · 拆解：三层结构（1:40–2:40）

〔屏幕：字卡「页面 → API route → 数据函数」〕

> 拆下来是三层：
> 1. **数据函数**：前六集写的那些（余额、价格、缓存）——一行不用改，直接复用，这是终端先行策略第一次兑现红利；
> 2. **API route**：一个 HTTP 接口把数据函数包起来，浏览器问它要 JSON；
> 3. **页面**：拿到 JSON 渲染成表格。
>
> 用 Next.js 的 App Router，前端和接口在同一个项目里——这也是我选 Next 而不是纯前端工程的原因。

## T4 · API route 包数据函数（2:40–3:50）

〔屏幕：`app/api/portfolio/[address]/route.ts` 雏形，现场敲〕

```ts
export async function GET(req, { params }) {
  const { address } = await params;
  const data = await getPortfolio(address);  // 前六集的函数
  return Response.json({ ok: true, data });
}
```

> `getPortfolio` 就是我 01–06 集在终端里攒出来的那套逻辑。包成接口只花了几行——之前每一集写的代码，今天一个都没扔。

## T5 · 页面 + react-query（3:50–5:00）

> 页面这边我先写了个裸 `useEffect` + `fetch`，能用。但去查了下，社区标配是 react-query——我研究了下它多出来的三件事：请求缓存（相同地址不会重复打接口）、失败自动重试、加载/出错的状态机。都是我手写要造的轮子，拿来主义。
>
> 页面上先渲染一个没有任何样式的 HTML 表格——丑就丑，这一集的重点是数据通。

## T6 · 实测（5:00–6:20）

〔终端起 dev 服务 → 浏览器打开 localhost:3000/portfolio〕

> `npm run dev`，浏览器打开——终端里那张表，现在在网页上了。改地址栏里的地址参数，表格跟着变，react-query 的加载状态一闪而过。
>
> 打开 Network 面板看了一眼：页面请求的是我自己的 `/api/portfolio/...`，中间层再去打节点——T2 的三层结构，眼见为实。

## T7 · 收束（6:20–7:00）

> 六集终端积木，一集搬上网页。这集我自己带走的：数据函数和界面之间隔一层 API route，不是架构洁癖，是 CORS 和密钥安全的现实要求；react-query 是我确认过的「值得引入的库」。
>
> 现在能看了。（停顿）但看到 USDT 1222 个，我想换成 ETH，还得去 Uniswap 官网——凭什么？下一集开始，我自己换：先问链一句「100 USDC 能换多少 WETH」。

# 需求 16《回答等十几秒，然后被掐断》策划案 · 思考流口播版

目标时长 6 分钟。视角铁律见 `lab/00-内容标准.md`。上集钩子：一轮回答十几秒，赶上默认限制直接 500。本集只解决「断」，不碰「慢」。

## 思考主线（先看骨架）

```
T1 复现断掉的那一刻 → T2 诊断：谁掐的 → T3 Edge runtime 是什么
→ T4 一行改动 → T5 实测：长对话活下来了 → T6 新问题：活了但傻等
```

## T1 · 复现断掉的那一刻（0:00–0:50）

〔屏幕：终端/浏览器里的 500 报错，提前录好〕

> 先把病发作出来：Copilot 问一个要连续调三个工具的问题——十几秒后，接口直接 500。（停顿）报错信息我盯了半天，没有任何一行说「你的代码错了」。那就是环境杀的。

## T2 · 诊断：谁掐的（0:50–1:50）

〔屏幕：笔记卡「Vercel Node 函数默认 10s 超时」〕

> 去查了托管平台的文档：Serverless Node 函数默认执行上限 10 秒——超时直接杀进程，管你算到哪一步。
>
> 我对着自己的链路算了笔账：一轮带工具的对话 = 模型思考几秒 + 工具读链几秒 + 可能还有第二轮……15 秒很正常。**这不是我的 bug，是我把 10 秒的盒子装了 15 秒的活**。诊断清楚后选项也清楚了：要么把活拆短（不现实，工具链就这长度），要么换个超时更长的运行时。

## T3 · Edge runtime 是什么（1:50–2:50）

〔屏幕：笔记卡「Edge runtime：轻量运行时，默认 30s」〕

> 查到的答案：Vercel 上同一份代码可以跑在两种运行时——默认的 Node 函数，或者 **Edge runtime**：更轻量、冷启动更快，默认执行上限 30 秒，还免费。
>
> 代价也要记下：Edge 不是完整 Node，部分 API 用不了。我核对了下自己的 route：就是发 HTTP、读流、转发——都是 Edge 支持的基本款，没踩雷。这段核对很重要：**换运行时不是免费的，先盘点依赖再动**。

## T4 · 一行改动（2:50–3:30）

〔屏幕：route 文件，现场加一行〕

```ts
export const runtime = "edge";
```

> 治疗方案就一行：在 Copilot 的 chat route 里声明跑 Edge。改完部署，深呼吸。

## T5 · 实测：长对话活下来了（3:30–4:50）

〔屏幕：同一条「三个工具连环调用」的问题重跑〕

> 复现用的同一条问题再跑一遍——十几秒后，回答完整落地，不再 500。（停顿）从报错到治好，改动一行，诊断花了十分钟。这集的信息量就一句话：**部署平台的默认限制是环境的一部分，写代码之前得知道盒子的尺寸**。
>
> 顺手看了眼响应时间：没变快，该 15 秒还是 15 秒。Edge 治的是「断」，不是「慢」。

## T6 · 新问题：活了但傻等（4:50–5:20）

> 现在回答能完整出来了，但体验依然是：点了发送，盯着空白等 15 秒，然后一整段话砸出来。工具调了什么、模型在想什么，用户全程蒙在鼓里。
>
> 能不能边生成边推？哪怕先出「我正在查报价……」也好。下一集：SSE，把一次回答拆成一条溪流。

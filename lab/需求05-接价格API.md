# 需求 05《余额有了，值多少钱？》策划案 · 思考流口播版

目标时长 6.5 分钟。视角铁律见 `lab/00-内容标准.md`。上集钩子：USDT 写着 1222，它值 1222 美元吗？

## 思考主线（先看骨架）

```
T1 链上没有价格 → T2 价格从哪来：CoinGecko → T3 第一个外部 API
→ T4 估值表 → T5 轮询，429 被教育 → T6 解药预告
```

## T1 · 链上没有价格（0:00–0:50）

〔屏幕：五链余额表输出〕

> 上集结尾的问题：这些余额值多少钱？我先想当然地去找「链上的价格」——查了半天发现这问题问错了：**链上根本没有价格**。账本只记录谁有多少，值多少钱是链下世界的事，由交易所的买卖决定。
>
> 所以给余额定价，必须走出链，接一个外部数据源。这是整个系列第一次调链外 API。

## T2 · 价格从哪来：CoinGecko（0:50–1:50）

〔屏幕：笔记卡「CoinGecko：把全交易所的价格聚合成一个数」〕

> 我选了 CoinGecko 的免费接口：它把几百个交易所的成交价聚合成一个「当前价」。肯定不精确——不同交易所略有差价——但对估值来说足够，而且免费档不要钱。
>
> 为什么不用更贵的专业行情 API？我的原则：先用免费的把事跑通，真撞墙了再升级，说不定根本不用升。

## T3 · 第一个外部 API（1:50–2:50）

〔屏幕：`lab/labs/05-prices.ts`，现场敲〕

```ts
const url = "https://api.coingecko.com/api/v3/simple/price" +
  "?ids=ethereum,tether&vs_currencies=usd";
const prices = await (await fetch(url)).json();
// { ethereum: { usd: 2347.97 }, tether: { usd: 0.9991 } }
```

> 一个 GET 请求，传币的 id 列表，回来现成的 USD 价格。这里有个小坑我踩了下：CoinGecko 用自己的 id（`ethereum`、`tether`），不是合约地址——所以我的代币清单里得加一列映射。成品代码里 `tokens.ts` 每个币都带一个 `coingeckoId`，就是这一集埋的。

## T4 · 估值表（2:50–3:40）

〔终端：跑〕

> 把 04 集的五链余额表乘上价格：每个代币一行「余额 × 单价 = 价值」，最后一行求和。第一次看到自己资产的总美元数——一个 API 调用，前面四集的所有积木就串成了结果。

## T5 · 轮询，429 被教育（3:40–5:20）

> 估值能算了，我贪心了一下：加个循环，每 5 秒刷一次，想做个「实时估值器」。（停顿）跑到第 40 秒——HTTP 429，Too Many Requests。再刷，还是 429。我被免费档限流正面教育了。
>
> 去查了文档：免费档大约每分钟 10–30 次请求，我 5 秒一次就是每分钟 12 次，理论上贴着线，实际上人家还有突发限制。撞了墙，我现在有两个选择：花钱升级，或者少发请求。
>
> （停顿）少发请求……可是余额 15 秒就得更新，价格 60 秒不用变——我突然反应过来：**我根本不需要每次都去要价格**。要过的价格放手里，没过期就直接用。这个东西是不是就叫缓存？

## T6 · 解药预告（5:20–5:40）

> 对，缓存。但缓存写起来简单，写对不容易：放多少条、活多久、满了挤谁。下一集，手写一个 30 行的 LRU + TTL 缓存，把 429 彻底治了。

## 实测清单

- 正常估值输出一次（成功镜头）
- 5 秒轮询直到 429（本集「意外镜头」，提前彩排好触发时长，约 40 秒）
- 429 的原始响应体打印出来（给观众看清错误长什么样）

## 笔记卡清单

- 「链上没有价格，价格是链下的事」
- 「CoinGecko id ≠ 合约地址，清单里要加映射列」
- 「429 = 免费档的时间窗口限制」

## 制作清单

- 口播自检：凡「记住/注意」改回「我发现/我撞上了」；
- 本机直连不了 CoinGecko，录制时用 `NODE_USE_ENV_PROXY=1 HTTPS_PROXY=http://127.0.0.1:7897 npx tsx lab/labs/05-prices.ts`（走本机代理，实测可用）；
- 429 现场要真实触发，彩排一次确定等待时长，录制时可加速剪辑但保留原始报错；
- 「缓存」两个字出现在结尾时可以卖个关子，别提前解释。

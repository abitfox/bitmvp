# 00 · BitMVP 视频系列 · 内容标准

本文件是这个系列所有策划案与成片必须遵守的标准。新写任何一集之前先通读；写完对照自检。标杆样例：`lab/需求01-读链第一步.md`。

## 1 · 系列定位

「终端里长出一个 Web3 工作台」。不讲 finished 项目，讲它怎么被一个个真实需求逼出来：

- **需求链驱动**：每一集的需求都必须从上一集的钩子里自然长出来，观众看完能预测下一集要干什么，又猜不到具体方案；
- **一集一个概念**：超载自查——列出这集要讲的知识点，超过一个概念就拆集；
- **终端先行**：纯数据获取/整合的需求，终端输出就是「最小 UI」，不做界面；UI 只在两种时刻出现：核心数据能力成型后的整合（07），以及没有界面就无法演示的需求（签名、流式）；
- **整合与总结靠后**：第一个页面之前不出 UI；知识点攒多了才做脑图总结（18）；最后才回到完整的 BitMVP（19）；
- 每集 5–8 分钟，最长不超 8.5 分钟。

## 2 · 叙事视角铁律（最重要）

探索者视角，不是教学视角。叙述者是**和我一起查资料、一起猜、一起踩坑的人**，观众是同行者不是学生。

- 全程用「我」，禁用「大家」「你们」；
- 禁语表：「记住」「注意」「你应该」「只需要知道」→ 一律替换为：「我去查了」「查了才知道」「我发现」「我猜……试试」「原来如此」；
- **需求必须有真实场景来历**：提币不放心、数字看不懂、嫌麻烦——先卡住，再行动；
- **概念的讲法固定为三拍**：我原来的理解（常常是错的）→ 查了才知道 → 一句人话 + 一个类比（账本、钥匙串、银行卡号这类生活物件，不堆术语）；
- **猜想要跨集验证**：拿不准的结论「立此存照」，在后面某集回收。这既是探索感的来源，也是集与集之间的黏合剂；
- 允许承认不懂：「这块我也只知道皮毛，够用就行」——装懂最毁这个系列。

## 3 · 每集五拍套路

| 拍 | 时长 | 内容 |
|---|------|------|
| 需求 | 30s | 一句人话说清要什么 + 真实场景来历，从上集钩子接过 |
| 怎么想 | 1–2min | 拆解：分几步、卡点在哪、方案为什么这么选（含被否掉的方案） |
| 最小实现 | 3–4min | 十几行代码现场敲，能跑就行，丑没关系 |
| 实测 | 1–2min | 终端或页面跑真实主网数据；至少安排一个「意外镜头」（报错、反直觉输出） |
| 钩子 | 30s | 这个方案哪里不够用 → 下一集的需求从这里长出来 |

## 4 · 策划案文档模板

每集一个文档，命名 `需求NN-标题.md`，放在 `lab/` 下。骨架固定：

```markdown
# 需求 NN《问句标题》策划案 · 思考流口播版
目标时长。视角铁律一行提醒。
## 思考主线（先看骨架）   ← T1→T2→… 一行流程图
## T1 · 段名（时间戳）     ← 〔屏幕〕提示 + 引用块口播（思考过程本身）
...
## 实测清单               ← 录制前备好的地址/命令/意外镜头
## 笔记卡清单             ← 概念段的学习笔记卡（不是教学 PPT）
## 制作清单               ← 含口播自检：凡「记住/注意」改回「我去查了/我发现」
## 发布信息               ← 简介一句话 + 封面创意
```

## 5 · labs 脚本约定

- 每个终端集配一个最小实现脚本：`lab/labs/NN-slug.ts`，观众 clone 后 `npx tsx lab/labs/NN-slug.ts` 直接跑；
- 纯终端输出，不打印花哨 UI；默认 RPC `https://ethereum-rpc.publicnode.com`（本机实测 llamarpc 不通，本身就是「公共 RPC 会抽风」的例证）；
- UI 集（07/11/13/16/17）不出脚本，在策划案里注明对应的成品代码文件；
- 脚本顶部注释一行：本集需求 + 对应策划案路径。

## 6 · 画面与制作约定

- 代码区保持 12 行以内，终端字号调大；
- 概念段配笔记卡放慢，代码段加速；深内容集标注字幕章节「懂的同学从 Tx 回来」；
- 可选镜头（如裸 curl 看 RPC 真面目）明确标注「可砍」，超时先砍它；
- 每集结尾报对应成品代码路径（`lib/chain/*` 等），视频与仓库互导。

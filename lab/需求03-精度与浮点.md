## T1 · 位数都不统一？（0:00–0:40）

〔屏幕：上集 multicall 原始输出〕

> 上集的输出我看了一晚上：同一个地址，USDT 余额是 11 位数，某 Meme 币是 24 位数。这些数除以多少才算钱？去查了——居然**每个代币自己说了算**。

## T2 · decimals 机制（0:40–1:50）

〔屏幕：笔记卡「decimals：合约自报家门」〕

> ERC-20 标准里有个 `decimals()` 函数，合约用它自报家门：我的最小单位是 10 的几次方。USDT 报 6（因为它从比特币生态继承的习惯），大多数币报 18。
>
> 为什么不统一？我去找了原因：标准只要求「有这个字段」，没规定值——早期设计者把自由留给了发行方，后来大家将错就错兼容到现在。历史包袱，但已成事实标准。
>
> 顺便补上 01 集的坑：ETH 的 18 位就是这么来的，`formatEther` 只是 `formatUnits(x, 18)` 的马甲。

## T3 · 浮点实验翻车（1:50–3:00）

> 搞懂了位数，我第一反应很简单：除以 10^n 不就完了？JS 里一行的事。（停顿）我先做了个实验，结果自己被打脸：

〔终端：现场跑〕

```ts
console.log(402143094812348905n);            // 402143094812348905
console.log(Number(402143094812348905n));    // 402143094812348900  ← 尾巴没了
console.log(0.1 + 0.2);                      // 0.30000000000000004
```

> JS 的 number 是浮点数，只有 15–17 位有效数字。链上余额动辄 18 位起步，转成 number 的那一刻，尾巴就悄悄丢了。（停顿）这不是显示问题，是**钱少了**——对账会对不上，四舍五入能吃掉真金白银。

## T4 · 我的整数铁律（3:00–3:40）

〔屏幕：笔记卡「全程整数，只在展示层换算」〕

> 所以我给自己立了条铁律：**金额全程用整数（bigint）存储和计算，只在打印那一刻换算成人类单位**。BitMVP 成品里所有金额走的都是这条路，数据库里甚至存的是字符串整数。
>
> 整数除法会丢余数怎么办？丢余数只影响「显示最后一位」，不影响账；而且换算只发生在展示层，账本数字从未变过。

## T5 · 三种代币换算表（3:40–4:50）

〔屏幕：`lab/labs/03-decimals.ts`，现场敲〕

> viem 给了 `formatUnits(value, decimals)`，decimals 从哪来？问合约——`readContract` 调 `decimals()`。我把上集 multicall 的输出配上各自的 decimals，打一张换算表：

```ts
for (const t of tokens) {
  const [raw, decimals] = await client.multicall(...); // balanceOf + decimals
  console.log(t.symbol, formatUnits(raw, decimals));
}
```

〔终端：跑〕

> USDT 精确到 0.000001，18 位的币长长一串——但每一个都是精确的。

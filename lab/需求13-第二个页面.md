# 需求 13《终端看不过瘾：第二个页面》策划案 · 思考流口播版

目标时长 6 分钟。视角铁律见 `lab/00-内容标准.md`。上集钩子：总不能一直盯着终端。本集刻意设计成 07 集套路的重复练习，节奏可以快。

```

→ T4 Radar 页面成型 → T5 实测：看块高跳 → T6 新问题：懒得查了
```

## T1 · 套路已经在手（0:00–0:30）

〔屏幕：07 集三层结构字卡回放〕

> 把扫区块搬上网页，套路 07 集已经练过：数据函数 → API route → 页面。这集我故意走快点，验证一个猜想：**第二次整合应该便宜很多**。

## T2 · 复用：route 包扫块函数（0:30–1:30）

〔屏幕：`app/api/radar/onchain/route.ts` 雏形〕

```ts
export async function GET() {
  const pulse = await getOnchainPulse();  // 12 集的扫块函数
  return Response.json({ ok: true, data: pulse });
}
```

> `getOnchainPulse` 就是 12 集终端里那套逻辑包了个函数名。route 三行。页面侧照抄 Portfolio 的 react-query 写法，改个接口地址。
>
> 猜想先验证一半：数据层零改动，接口三行，页面复制粘贴微调——第二次整合确实便宜。

## T3 · 自动刷新的抉择（1:30–2:30）

〔屏幕：笔记卡「块高 12 秒一跳，页面就 12 秒一刷」〕

> 有个新决策：终端时代我自己手动循环，页面上怎么持续更新？我去想了下几个选项：手动点刷新（信息会过期）、WebSocket 推送（要维持长连接，重）——最后选了最朴素的**定时轮询**：以太坊 12 秒一个块，我就 12 秒刷一次，跟链的翻页节奏对齐。
>
> react-query 自带 `refetchInterval`，一行配置。有时候选方案的理由不是高级，是跟节奏合拍。

## T4 · Radar 页面成型（2:30–3:20）

〔屏幕：页面雏形，无样式表格：块高 / 交易数 / Gas / 大额转账列表〕

> 页面四块信息：最新块高、块内交易数、Gas 拥挤度、大额转账列表。还是素表格——这个系列的风格：数据通了再说脸面。

## T5 · 实测：看块高跳（3:20–4:40）

〔屏幕：页面前置录屏 2 分钟，压缩成 30 秒〕

> 页面挂着不动，看它自己活：块高从 …258 跳到 …259 再跳 …260，交易数跟着变，Gas 涨了又落。（停顿）我挂了十分钟，中途逮到一笔大额转账自己蹦进列表——没人盯屏，它自己长出来的。
>
> 上集是我在扫链，这集是页面在替我扫。两个页面挂在一起，一个看自己、一个看别人，BitMVP 的雏形第一次有点「产品」的意思了。

## T6 · 新问题：懒得查了（4:40–5:10）

> 现在我有五个能力：查余额、算估值、报价、扫链、看页面。但我发现更懒的需求来了——我连页面都不想挨个看，我想直接问：「以太坊最近有大额转账吗？」让一个东西替我把前面这些函数全跑了。
>
> 能干这事的东西我听说过：AI，function calling。但它是怎么替人调函数的？下集从零试。

## 实测清单

- Radar 页面挂机 2 分钟录屏（块高至少跳 5 次）
- 大额转账自动入列的瞬间（提前彩排确认当天主网有鲸鱼活动；没有就录「安静状态」并口播点破）
- 轮询间隔与实际出块速度的对照（Network 面板请求频率截图）

# 需求 14《懒得自己查了，让 AI 替我问》策划案 · 思考流口播版

目标时长 7.5 分钟。视角铁律见 `lab/00-内容标准.md`。上集钩子：想直接问「以太坊最近有大额转账吗」，让 AI 替我把函数全跑了。本集全程终端。

## 思考主线（先看骨架）

```
T1 AI 凭什么能查链 → T2 function calling 的机制 → T3 给模型一份「工具说明书」
→ T4 两轮对话的实现 → T5 实测：它真的调了 → T6 新问题：一个工具不够
```

## T1 · AI 凭什么能查链（0:00–0:40）

〔屏幕：终端 + 一个聊天框的拼图〕

> 我想要的效果：打个字「vitalik 有多少 ETH」，AI 自己去链上查了再回答我。但 AI 模型是个纯文本机器——它连网络都上不了，凭什么能查链？
>
> 先说破除一个我以为：AI 不是自己去「上网搜索」。是我把**我的函数**递给它，它决定什么时候调、传什么参数，**执行的是我的代码**。这套机制叫 function calling。

## T2 · function calling 的机制（0:40–1:50）

〔屏幕：字卡「模型只做决定，干活的是我的代码」〕

> 我把机制拆成四步说给自己听：
> 1. 我给模型一份「工具说明书」：有个函数叫 getBalance，参数是 address，它能查余额；
> 2. 用户提问，模型读到问题，**自己判断**该调这个工具，并生成参数；
> 3. 模型把「我要调 getBalance，参数是这个地址」发回来——注意它只是说，不执行；
> 4. **我**在本地执行函数，把结果还给它，它拿到数字再组织成回答。
>
> 模型像一位只动嘴的顾问：说该查什么，不碰键盘。执行权、数据权全在我手里——这个设计后面会显得特别重要（15 集）。

## T3 · 给模型一份「工具说明书」（1:50–3:00）

〔屏幕：`lab/labs/14-tool-call.ts`，工具 schema 部分〕

```ts
const tools = [{
  type: "function",
  function: {
    name: "get_balance",
    description: "查询以太坊地址的 ETH 余额",
    parameters: { type: "object", properties: {
      address: { type: "string", description: "0x 开头的地址" } },
      required: ["address"] },
  },
}];
```

> 这就是工具的全部定义：名字、干什么、参数长什么样。`description` 不是给人看的，是给模型看的——它全靠这段话决定「这个问题该不该用这个工具」。写清楚它「能干什么」比写「怎么干」重要，这是我自己踩过坑以后才改的写法（15 集展开）。

## T4 · 两轮对话的实现（3:00–4:20）

〔屏幕：对话循环代码〕

> 主流程是个循环：第一轮把问题和工具说明书发给模型；如果它回了 `tool_calls`，我本地执行函数，把结果作为一条 `role: "tool"` 的消息再发回去；第二轮它拿到数字，组织成人话回答。循环直到它不再要工具。
>
> 代码量比想象小：核心就是「把执行结果喂回去」这一个动作。

## T5 · 实测：它真的调了（4:20–6:20）

〔终端：跑 `lab/labs/14-tool-call.ts`，打印每轮消息〕

> 问它：「vitalik 有多少 ETH？」——终端里能看到第一轮它回了 `tool_calls`，参数 `0xd8dA…` 是它自己填的；我的脚本执行 `getBalance`，把 0.4021 ETH 喂回去；第二轮它答：「vitalik 的地址目前持有约 0.4021 ETH」。
>
> （停顿）我全程没告诉它答案，答案是我 01 集那个函数查的。数字是真的，因为链是真的。
>
> 再试一个陷阱问题：「 Arbitrum 上 vitalik 有多少 ETH？」——它老老实实说工具只支持以太坊主网，问我要不要先扩展。没瞎编。模型守不守规矩，一半看工具说明书怎么写。

## T6 · 新问题：一个工具不够（6:20–6:50)

> 单工具打通了。但我的函数已经攒了一堆：余额、估值、报价、扫块。全都注册进去，模型会不会选错？说明书怎么写才不打架？一堆工具的执行器怎么管理？
>
> 下一集：把一整个数据层的函数变成 AI 的工具集。

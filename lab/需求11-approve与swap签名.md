# 需求 11《报价到成交：approve + swap 两步签名》策划案 · 思考流口播版

目标时长 8 分钟。视角铁律见 `lab/00-内容标准.md`。上集钩子：知识全通了，钱怎么真的动。本集必须连钱包 + 有 UI（签名没法用只读请求糊弄），是写链幕的收官。

## 思考主线（先看骨架）

```
T1 只读时代的结束 → T2 一笔交易的生命周期 → T3 凭什么 Router 能动我的钱：approve
→ T4 两步状态机 → T5 测试网演练 → T6 实测与回执 → T7 收束 + 新方向
```

## T1 · 只读时代的结束（0:00–0:40）

〔屏幕：前几集报价画面快闪〕

> 到今天为止我干的全是「读」：余额、报价、扫链。换币的最后一公里是「写」——真把交易发出去。写和读隔着一整个世界：这次要动真金白银，我先想清楚再动手。

## T2 · 一笔交易的生命周期（0:40–1:40）

〔屏幕：字卡「构建 → 签名 → 广播 → 等回执」〕

> 我去拆了链上写的流程，四步：
> 1. **构建**：把「拿 100 USDC 换 WETH」翻译成一笔交易请求；
> 2. **签名**：钱包弹出确认框，我按确认——本质是我用私钥给这笔交易盖章（T4 那集说过：钱包里存的是钥匙）；
> 3. **广播**：签完的交易扔进网络，等矿工打包；
> 4. **回执**：交易上链，拿到交易哈希，状态可查。
>
> 每一步都可能失败，所以 UI 必须把状态亮出来，不能转圈转到底。

## T3 · 凭什么 Router 能动我的钱：approve（1:40–3:00）

〔屏幕：笔记卡「approve：授权书，不是付款」〕

> 拆到执行层我卡住了：Swap 由 Uniswap 的 Router 合约代劳，可我的 USDT 在**我**的地址上——合约凭什么能动我的钱？
>
> 查了 ERC-20 的授权模型：默认谁也动不了你的代币，除非你先调 `approve(-router-地址, 数量)` 立一张授权书。所以真实流程是两步：**先 approve 授权，再 swap 成交**。授权书还有额度概念，批多少花多少。
>
> 我突然明白为什么钱包弹窗要分两次确认了——以前我以为那是烦人，现在是两道不同性质的门：一张是授权书，一张是成交单。

## T4 · 两步状态机（3:00–4:00）

〔屏幕：字卡状态机「idle → approving → swapping → done/error」〕

> 我把两步画成状态机：`approving`（等授权上链）→ `swapping`（等成交上链）→ `done`，任何一步失败进 `error` 并停在原地。
>
> 这就是成品 `useSwapExecution.ts` 的骨架。以前看 Uniswap 界面上「Step 1/2」的进度条，今天知道它背后就是这台状态机。

## T5 · 测试网演练（4:00–5:20）

〔屏幕：MetaMask 切到 Sepolia 测试网，水龙头领测试币〕

> 不拿主网真钱练手。Sepolia 测试网的币是水龙头免费领的，链的玩法跟主网一模一样——这也回应了 01 集的话：链不是公司，测试网和主网是两本独立账，规则相同。
>
> 我的 Swap 面板加了链选择器（成品里就有 Sepolia 测试网选项，今天用上了）。

## T6 · 实测与回执（5:20–7:00）

〔屏幕：页面操作全流程录屏〕

> 走一遍：输入 100 USDC → 报价出现（08–10 集的读链能力现场复用）→ 点 Swap → 钱包弹出第一笔 approve 确认 → 状态机亮「授权中」→ 上链后自动进第二笔 swap → 等待 → done，出交易哈希。
>
> 点开哈希在区块浏览器里看：我的地址少了 100 USDC，多了 WETH。全链路打通了。（停顿）从 01 集的 `getBalance` 到今天动账本，一共 11 集。

## T7 · 收束 + 新方向（7:00–7:30）

> 这集带走的：写链四步生命周期；approve 是授权书不是付款；两步状态机是所有 DApp 交易 UI 的通用骨架。
>
> 自己的钱能管了。但我盯着 Portfolio 页面发呆：我的资产全链路透明，别人的呢？大鲸鱼现在在干嘛？——这个问题的答案不在我的地址里，在**别人的交易**里。下一集换个方向：扫区块。

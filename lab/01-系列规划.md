# 07 · 视频系列规划：终端里长出一个 Web3 工作台

定位：不讲「 finished 项目」，讲「它怎么被一步步逼出来」。每一集 = 一个小需求，走同一条循环：

> 遇到需求 → 我怎么想 → 怎么拆解 → 最小化实现（纯数据需求直接终端输出）→ 实测 → 留一个钩子，自然催生下一个需求。

原则：**一集只解决一个概念**。终端先行，不碰 UI；核心数据能力攒够了才做第一个页面；知识点攒多了才做一轮脑图总结；最后才是完整的 BitMVP。每集 5–8 分钟。

## 需求链总览

```
01 查ETH余额 → 02 读ERC-20 → 03 数字看不懂 → 04 五条链都要 → 05 值多少钱 → 06 被限流了
     (以上全部终端输出，核心数据能力成型)
→ 07 每次跑脚本太麻烦 → 第一个页面（UI 整合）
→ 08 光看不能动，想换币 → 报价 → 09 哪个池子最划算 → 10 ETH怎么变WETH → 11 签名成交
→ 12 别人在买什么 → 扫区块 → 13 想随时看 → 第二个页面
→ 14 懒得自己查 → 让 AI 去查 → 15 工具变多了怎么管 → 16 回答被掐断 → 17 逐字输出
→ 18 知识点太多了 → 脑图分类总结
→ 19 复盘：一份链上数据层的架构验证 → 完整的 BitMVP
```

## 第一幕 · 读链（01–06，全程终端）

| # | 需求（标题即钩子） | 拆解与方案 | 对应成品代码 |
|---|------|-----------|---------|
| 01 | 这个地址有多少 ETH？ | 数据在节点状态里 → 问公共 RPC → viem 三行 `getBalance` → 引出 wei 与单位换算 | `lib/chain/portfolio.ts` 的雏形 |
| 02 | 钱包里大头是 USDT 这些 ERC-20，怎么读？ | 每个代币一次 `readContract`，20 个代币慢到没法用 → Multicall3 一条请求打包全部 | `lib/chain/portfolio.ts` |
| 03 | `402143094812348905` 是多少钱？ | 链上只有整数（最小单位），decimals 与格式化；为什么全程整数计算、不碰浮点 | `lib/chain/tokens.ts` |
| 04 | 我在五条链上都有资产 | 链配置化（chains.ts），`Promise.all` 并行；终端输出一张五链余额表 | `lib/chain/chains.ts` |
| 05 | 余额有了，值多少钱？ | 只做一件事：接 CoinGecko 拿价格，终端输出 USD 估值——然后被免费档限流现场教育 | `lib/chain/prices.ts` |
| 06 | 请求老是被 429 拒掉，怎么办？ | 上一集的解药：手写 30 行 LRU + TTL 缓存，命中、过期、淘汰三件事；为什么不上 Redis | `lib/chain/cache.ts` |

| 07 | 每次开终端跑脚本太麻烦，想随时打开就看 | 把终端表格搬进网页：一个 API route 包住前面的数据函数，react-query 拉数据——第一轮 UI 整合，只做展示不做样式和交互 |

## 第三幕 · 写链（08–11）

| # | 需求 | 内容 |
|---|------|------|
| 08 | 光看不能动，我想换币。能换多少，先问链 | 只做报价：Quoter 合约传入代币对和数量，终端输出能换多少——报价的本质是一次合约读操作（主网只有 Quoter V1，签名和 V2 还不一样——本集的真实踩坑） |
| 09 | 同一个兑换，价格不一样，听谁的 | Uniswap V3 的 fee tier（500/3000/10000）：三个池子并行查，取最优——并行询价的第一次实战 |
| 10 | 我明明选的 ETH，合约里怎么是 WETH | 原生币不是 ERC-20，报价和成交前要先「包装」；新手最容易懵的一集，讲透它 |
| 11 | 报价到成交，钱怎么真的动 | approve + swap 两步签名，wagmi 每步状态回显；这一集必须有钱包和 UI，前面铺垫全部收口 |

## 第四幕 · 信号与 AI（12–17）

| # | 需求 | 内容 |
|---|------|------|
| 12 | 别人在买什么？ | 只做终端：直连 RPC 扫最新区块，解析交易列表，捞大额转账和 Gas 拥挤度——鲸鱼转账是从区块里捞出来的真实记录 |
| 13 | 终端看不过瘾，想随时盯着 | 第二个页面：把扫区块搬上网页，复用 07 的套路，这次应该熟练了（降级容错见插集） |
| 14 | 我懒得自己查了，让 AI 替我问 | LLM 访问不了链 → 把一个查询函数包成 function calling 工具（工具 schema 长什么样、模型怎么决定调谁）；终端跑通一轮真实对话：问「100 USDC 换 WETH 报价多少」，它真去链上询价 |
| 15 | 一个工具不够用了 | 把 `lib/chain` 的一批函数批量注册成工具集；模型选错工具怎么办（工具描述怎么写）；为什么工具集从数据层生成——AI 查不到产品里没有的能力，乱承诺从架构上被堵住 |
| 16 | 回答等十几秒，然后被掐断 | 先现场复现 Vercel Node 函数 10s 超时报错；换 Edge runtime 解决——只解决「活下来」这一件事 |
| 17 | 能活还不够，要逐字出 | SSE 流式：事件类型怎么设计（text / reasoning / tool_call / tool_result），用 curl 直接看流；前端打字机效果对应成品 `ChatPanel` |

## 每集固定套路

1. **需求**（30 秒）：一句人话说清要什么，最好从上一集的钩子接过来；
2. **怎么想**（1–2 分钟）：这个需求拆成几步、卡点在哪、方案为什么这么选；
3. **最小实现**（3–4 分钟）：十几行代码，能跑就行，丑没关系；
4. **实测**（1–2 分钟）：终端或页面跑真实主网数据；
5. **钩子**（30 秒）：这个方案哪里不够用 → 下一集的需求从这里长出来。

## 制作约定

- 全系列内容统一放在仓库 `lab/` 目录：`00-内容标准.md`（所有策划案的写作标准）、本规划、各集策划案（`需求NN-标题.md`）、最小实现脚本（`labs/NN-slug.ts`）；
- 终端集的脚本观众可以 clone 下来跟着跑，`npx tsx lab/labs/01-balance.ts` 直接运行；UI 集不出脚本，策划案里注明对应成品文件；
- 终端输出就是「最小 UI」，够表达核心逻辑就不做界面；
- 每集结尾报对应成品代码路径（`lib/chain/*`），视频与仓库互导。

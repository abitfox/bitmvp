# 需求 10《我明明选的 ETH，合约里怎么是 WETH》策划案 · 思考流口播版

目标时长 6.5 分钟。视角铁律见 `lab/00-内容标准.md`。上集钩子：原生 ETH 在合约世界里「查无此人」。

## 思考主线（先看骨架）

```
T1 报错现场 → T2 原生币为什么不是 ERC-20 → T3 WETH：包装戏法
→ T4 两个余额对一对 → T5 报价路径统一 → T6 新问题：钱怎么真的动
```

## T1 · 报错现场（0:00–0:30）

〔屏幕：上集结尾的报错〕

> 把原生 ETH 的零地址填进 Quoter，报错「invalid address」。这不是 bug，是我对链上资产的理解缺了一块。今天把这块补上。

## T2 · 原生币为什么不是 ERC-20（0:30–1:40）

〔屏幕：笔记卡「原生币是账本的本命字段，合约世界里查无此人」〕

> 我去想明白了一件事：ETH 的余额是账本的**本命字段**——01 集的 `getBalance` 直接问账本要，不走任何合约。而 ERC-20 是一套合约标准，函数签名、事件、decimals 一样不缺。
>
> 所以对合约来说，ETH 是个「没有话术清单的哑巴」：它没有 `balanceOf`，没有 `transfer`，任何只认 ERC-20 的合约（包括 Quoter、Router）都跟它说不上话。

## T3 · WETH：包装戏法（1:40–2:50）

〔屏幕：笔记卡「WETH = 把 ETH 锁进合约，发一张凭证」〕

> 解法聪明得很：有个 WETH 合约，你把 ETH 打给它，它 1:1 发你一张「凭证」——这个凭证是标准的 ERC-20，全合约世界都认识。想赎回？调 `withdraw`，凭证销毁，ETH 退回。
>
> WETH 全称 Wrapped ETH，「包装」二字就这意思。我去看了下 WETH 合约的代码，居然短得离谱——核心就 deposit/withdraw 两个函数。

## T4 · 两个余额对一对（2:50–4:00）

〔屏幕：`lab/labs/10-weth.ts`，现场敲〕

```ts
const eth = await client.getBalance({ address });
const weth = await client.readContract({ address: WETH, abi: erc20Abi,
  functionName: "balanceOf", args: [address] });
console.log("ETH:", formatEther(eth), "WETH:", formatEther(weth));
```

> 跑 vitalik 的地址：ETH 5.77，WETH 1.47——两个都非零。这下亲眼看到了「包装」的痕迹：这是两本独立的账，一个在账本本命字段，一个在 WETH 合约里。上一集我以为的「同一个币」，其实是两个东西。

## T5 · 报价路径统一（4:00–5:20）

> 那报价怎么办？规则就一条：**用户界面上说 ETH，进合约前统一换成 WETH**。我改了脚本：用户选 ETH，`tokenIn` 自动填 WETH 合约地址，100 ETH 的报价立刻出来了。
>
> 成品代码（`lib/chain/swap.ts`）里就是这么写的：一个 `if (isNative) 用WETH` 的映射，把「用户视角」和「合约视角」的差异消化在一处。以后所有报价逻辑都不用再操心这件事。

## T6 · 新问题：钱怎么真的动（5:20–6:00）

> 报价、费率、包装，三块拼完，我发现换币的「知识」部分全通了。但是到今天为止，我没花出去一分钱——因为花钱需要另一套东西：签名、授权、广播。
>
> 这些没法用只读请求糊弄，必须连钱包。下一集，真刀真枪：approve + swap，两步签名把这笔交易做完。为了不拿真金白银练手，我准备去测试网。

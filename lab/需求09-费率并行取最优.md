# 需求 09《同一个兑换，价格不一样：fee tier》策划案 · 思考流口播版

目标时长 6.5 分钟。视角铁律见 `lab/00-内容标准.md`。上集钩子：一对代币之间有好几个池子，哪家价最好？

## 思考主线（先看骨架）

```
T1 报价跟网页对不上 → T2 V3 的池子结构：fee tier → T3 三档并行询价
→ T4 取最优 + 它的局限 → T5 实测对比表 → T6 新问题：ETH 报错说要 WETH
```

## T1 · 报价跟网页对不上（0:00–0:40）

〔屏幕：上集对账画面回放〕

> 上集对账差的那一点，我以为只是时间差。后来翻 Uniswap 界面，看到费率选项——0.05%、0.3%、1% 才反应过来：**同一个交易对，V3 里按费率分了多个独立池子**。我上集只问了其中一个。

## T2 · V3 的池子结构：fee tier（0:40–1:50）

〔屏幕：笔记卡「fee tier：按波动性选池子的手续费」〕

> 我去补了 Uniswap V3 的课：每个池子向交易收一笔手续费，归流动性提供者。费率有三档——0.05%、0.3%、1%。
>
> 为什么不统一？猜一下也能对：稳定币对（USDC/USDT）波动小，0.01% 的滑点都嫌多，用低费率；小币对波动大，流动性提供者要更高的费率补偿风险。所以主流对 usually 在低费率池子，长尾币在高费率池子。我的猜想：**USDC→WETH 最优大概率在 500 档**。记下来，实测验证。

## T3 · 三档并行询价（1:50–2:50）

〔屏幕：`lab/labs/09-fee-tiers.ts`，现场敲〕

```ts
const FEE_TIERS = [500, 3000, 10000];
const quotes = await Promise.all(
  FEE_TIERS.map((fee) => quoteSingle(USDC, WETH, 100e6, fee)),
);
const best = quotes.reduce((a, b) => (b.amountOut > a.amountOut ? b : a));
```

> 04 集练的链间并行又用上了：三个池子三个请求同时发。`reduce` 取 output 最大的。

## T4 · 取最优 + 它的局限（2:50–3:40）

〔屏幕：笔记卡「最优 = 换到最多？先这么简化」〕

> 「最优」我这里简化成「出得最多」。说句实话这不是完整答案：真实交易还要看深度、滑点、路由聚合——专业聚合器会跨池子拆单。我今天只学「挑最划算的单池」，简化边界先划清楚，别装懂。

## T5 · 实测对比表（3:40–5:20）

〔终端：三档报价对比 + 耗时〕

> 三档报价打出来了：500 档 0.04296、3000 档 0.04288、10000 档 0.04229——三档都有价，但高低立见。我的猜想验证了：USDC→WETH 最优就在 500 档。
>
> 三档并行总耗时 1.2 秒，跟单档几乎一样——又是并行的红利。输出一张「费率 | 报价 | 耗时」的小表，选最优一目了然。（数字每次实时会变，录制以当场输出为准，量级关系不变）

## T6 · 新问题：ETH 报错说要 WETH（5:20–6:00）

> 我顺手想测「ETH 换 WETH」——毕竟真实用户手里攥着的是 ETH。把 tokenIn 填成以太坊原生 ETH 的零地址，跑——（停顿）报错了。Quoter 说它不认识这个地址。
>
> 查了下原因，信息量比想象大：原生 ETH 根本不是 ERC-20，合约的世界里它「查无此人」。那我钱包里的 ETH 怎么参与换币？下一集：WETH 的包装戏法。
